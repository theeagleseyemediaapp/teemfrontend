# STRICT RULES — eagle-s-eye-parliament

Generated: 2026-06-26  
Reason: Prevent the exact breakage sequence that wasted hours today.

---

## 1. Package Manager

- **NEVER use `npm install`** — npm 11.x has an arborist bug that throws `Invalid Version:` on this project's dependency tree.
- **ALWAYS use `pnpm install`** — pnpm 11.x works correctly with this lockfile.
- If pnpm is not installed: `npm install -g pnpm` then run `pnpm install`.
- **NEVER delete `package-lock.json`** — Vercel's build system reads it. Without it, Vercel cannot resolve dependencies.
- **NEVER regenerate `package-lock.json`** — the existing one is pinned and works.

## 2. Config Files — DO NOT TOUCH

These files are already in their correct state. Changing them causes breakage:

| File | Reason |
|------|--------|
| `package.json` | Contains exact deps for `@lovable.dev/vite-tanstack-config`. Removing/changing it breaks the Lovable build wrapper. |
| `package-lock.json` | Pinned dependency tree. Regenerating causes version drift and Vercel build failures. |
| `vite.config.ts` | Uses `@lovable.dev/vite-tanstack-config` which bundles `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, `nitro`, and path aliases. Removing it causes 20+ plugin errors. |
| `tsconfig.json` | Path alias `@/*` → `./src/*` is required by the Lovable config wrapper. |
| `.gitignore` | Already correct. Do not add `node_modules/` back — mobile workspace needs its own `node_modules/` inside `apps/mobile/`. |

## 3. Workspace Structure

- The root is a **monorepo** with workspaces: `apps/*` and `packages/*`.
- `apps/mobile` is a **standalone Expo project** — it has its own `package.json` and `node_modules/`. Do NOT move it or merge its deps into the root.
- `packages/api` is a **local file dependency** for the mobile app (`"@eagles-eye/api": "file:../../packages/api"`). Do NOT delete it.
- The **web app** consumes packages via the root `node_modules/` symlinked by pnpm workspaces.
- If you must add a root dep, add it to the root `package.json` ONLY — never edit workspace `package.json` files unless working on that specific app.

## 4. Asset Files

- `src/assets/real/*.asset.json` are **auto-generated by Lovable CDN**. They contain `url` pointers.
- **NEVER delete these files** — they are imported by `src/lib/articles.ts` and the app crashes without them.
- If missing, restore from git: `git checkout HEAD -- src/assets/real/`

## 5. Pre-Push Checklist

Before ANY push to GitHub/Vercel:

```bash
git status                    # confirm only intended files changed
git diff --stat               # review exact changes
pnpm install                  # confirm deps resolve
pnpm run build                # confirm build passes locally
git push
```

- If `pnpm run build` fails, **fix it before pushing**. Do not push broken state.
- **NEVER force-push** to `main` — this is a Lovable-connected repo and force-pushing rewrites project history.

## 6. Environment Variables

- `.env` files are **gitignored** — never commit secrets.
- Copy `.env.example` → `.env` and fill in real values locally.
- Vercel env vars are set in the Vercel dashboard, not in code.

## 7. Database Migrations

- All schema changes go in `backend/migrations/` as timestamped `.sql` files.
- Run migrations via `supabase db push` or the Supabase SQL editor.
- Never edit an existing migration after it has been applied to the database.

## 8. Lovable-Specific Rules

- This project is connected to Lovable. The `@lovable.dev/vite-tanstack-config` package is a **black-box wrapper** — do not try to "improve" or replace it.
- The Lovable plugin injects: `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, `nitro` (build-only, Cloudflare default), `componentTagger` (dev-only), VITE_* env injection, `@` path alias, React/TanStack dedupe, error logger plugins, and sandbox detection.
- If you need extra Vite config, pass it inside `defineConfig({ vite: { ... } })` — do NOT add duplicate plugins.

## 9. What NOT To Do

| Action | Why |
|--------|-----|
| `npm install` | Crashes with `Invalid Version:` on this project |
| Delete `package-lock.json` | Vercel needs it; breaks install |
| Edit `vite.config.ts` plugins | Lovable wrapper manages 10+ plugins internally |
| Delete `src/assets/real/*.asset.json` | App crashes on SSR |
| Move `apps/mobile` or `packages/api` | Mobile app is standalone; web depends on workspaces |
| `git push --force` to main | Rewrites Lovable project history |
| Use `.npmrc` with `registry=https://registry.npmmirror.com` | Causes silent package corruption (empty `package.json` files in `node_modules`) |
| Run `npm cache clean --force` then `npm install` | Does not fix the arborist bug; wastes time |

## 10. If Build Breaks

1. Read the error carefully — 90% of issues are missing files or wrong package manager.
2. Check this file for the relevant rule.
3. If the issue is a missing `node_modules/` package, run `pnpm install`.
4. If the issue is a missing asset, run `git checkout HEAD -- src/assets/real/`.
5. If the issue persists, **revert config files to the last known good commit** and re-apply only the intended source changes.
